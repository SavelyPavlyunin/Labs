Многопоточный конвейер обработки данных Лабораторная работа №8

Проект представляет собой консольное Java-приложение, реализующее расширяемый конвейер для автоматического поиска и параллельной обработки текстовых данных. В рамках работы продемонстрировано совместное использование механизмов метапрограммирования (аннотаций и рефлексии), функционального стиля обработки коллекций и высокоуровневой многопоточности.

Основной стек технологий
Java Core (Кастомные аннотации, Reflection API)
Stream API (функциональная фильтрация, трансформация и сортировка коллекций)
Java Concurrency Utilities (`ExecutorService`, пулы потоков, потокобезопасные коллекции)
Java NIO (`Files`, `Paths` для работы с файловой системой)



Содержание и архитектура заданий

Проект спроектирован по модульному принципу и разделен на несколько логических компонентов, взаимодействующих между собой во время выполнения программы:

1. Создание кастомной аннотации `@DataProcessor`
Суть задачи: Разработка метаданных-маркеров для гибкого и динамического подключения новых модулей обработки без изменения основного кода системы.
Реализация:
   Аннотация ограничена использованием только на уровне методов (`ElementType.METHOD`).
   Жизненный цикл аннотации установлен в `RetentionPolicy.RUNTIME`, что делает её доступной для анализа в оперативной памяти во время работы приложения.
   Добавлен параметр `name` со значением по умолчанию для логирования работы процессоров.

2. Реализация модулей-обработчиков (Процессоров)
Суть задачи: Создание независимых классов, содержащих изолированную бизнес-логику трансформации текстовых строк с использованием **Stream API**.
Реализация: 
   Разработан класс `FilterAndTransformProcessor` для фильтрации строк по длине и их перевода в верхний регистр.
   Разработан класс `SortAndSortProcessor` для очистки строк от граничных пробелов (`trim`), удаления пустых элементов и финальной сортировки по алфавиту.
   Все целевые методы внутри классов помечены разработанной аннотацией `@DataProcessor`.

3. Разработка многопоточного менеджера данных `DataManager`
Суть задачи: Координация всего жизненного цикла данных: от загрузки из внешнего источника до параллельного распределения задач по потокам.
Реализация:
  Загрузка и сохранение: Методы `loadData` и `saveData` используют потоки ввода-вывода NIO для чтения/записи файлов с механизмом защиты (fallback на дефолтные данные при отсутствии источника).
  Рефлексия: Метод `processData` динамически сканирует зарегистрированные объекты, находит методы с аннотацией `@DataProcessor` и извлекает их метаданные.
  Многопоточность: Каждый найденный метод оборачивается в асинхронную задачу и отправляется в пул потоков `ExecutorService`. Локальные результаты параллельных вычислений безопасно аккумулируются в общем синхронизированном списке.



Ключевые инструменты и методы

В коде активно используются следующие механизмы Java:
`@interface` (Аннотации) — инструмент добавления метаданных, позволяющий размечать код для его последующего автоматического анализа сторонними компонентами.
`Reflection API` (`Method`, `invoke`) — механизм, позволяющий программе исследовать собственную структуру классов «на лету» и динамически вызывать методы объектов без жесткого прописывания их имен в коде.
`Stream API` (`stream()`, `filter()`, `map()`) — декларативный стиль манипуляции данными, упрощающий агрегацию, фильтрацию и сортировку коллекций.
`ExecutorService` — высокоуровневый интерфейс пула потоков, оптимизирующий распределение параллельных задач обработки и адаптирующийся под количество ядер процессора.
`Collections.synchronizedList` — обертка-синхронизатор, обеспечивающая потокобезопасность (`Thread-safety`) при одновременной записи результатов из разных рабочих потоков в общую коллекцию.
